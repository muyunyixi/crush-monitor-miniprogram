# Crush Monitor 小程序 · 微信识字验证 v0.4.2

微信真机已经验证：原生输入框长按粘贴可以一次收到多条微信聊天消息，本机对话保存、增量追加、选取截图也已经验证。现在继续验证现有 Cloudflare Worker 调用微信 OCR 的完整流程。

## 导入与真机测试

1. 下载此仓库，解压到本机。
2. 微信开发者工具 → 导入项目 → 选择含有 `project.config.json` 的仓库根目录。
3. 项目配置中的 AppID 是对应已提供截图中的小程序 AppID；如你的测试小程序不同，导入时选择自己的 AppID。
4. 点击「编译」「预览」，用手机微信扫码。
5. 在微信聊天多选复制文字，回到小程序长按输入框粘贴，点击「保存新增记录」。
6. 退出再进入，确认文字仍在。再次复制整段旧记录加新消息，观察只追加新增的行；同一段再次提交应提示内容已保存。
7. 点击「新建对话」、更改标题并保存。

此版按**聊天消息**存储：识别微信复制记录的昵称与时间，将它们作为消息信息显示，不再误当作独立消息；首次打开时会整理旧版本本机保存的微信记录。重复检测处理整段重贴或与上一批尾部重叠的消息，暂不是通用内容去重。无法识别消息边界的纯文本需要人工校对。

正式版的对话操作以聊天对象为入口：选中对象后粘贴或识字即可继续追加，不要求每次点击“保存新增记录”。清空和删除需由用户明确选择；此验证版保留按钮，便于核对增量追加的结果。截图识别后只展示可编辑的文字，不展示图片预览。

## 验证微信 OCR

1. 在**现有** Cloudflare Worker 的「Settings → Variables and Secrets」添加 `WECHAT_APP_ID` 和 `WECHAT_APP_SECRET`，其中 `WECHAT_APP_SECRET` 必须设为 Secret。使用与微信开发者工具中相同的小程序 AppID。不要把 AppSecret 发到聊天、写进 GitHub 或小程序源码。
2. 在微信小程序平台「开发管理 → 开发设置 → 服务器域名」配置现有 Worker 的 HTTPS 自定义域名，同时加入 **uploadFile 合法域名**与 **request 合法域名**。前者上传图片，后者查询识字结果；必须填写同一个完整 HTTPS 域名，均不加接口路径。
3. 小程序默认连接 `https://crush-monitor-mobile-api.muyunyixi.cloud`，直接选择最多四张相册图片即可。仅更换后端时修改页面内的 Worker 地址，**不要**附加 `/api/mini/ocr`。
4. Worker 收到截图后立即返回随机任务编号，后台用临时 `wx.login` 代码验证小程序身份并调用微信 OCR。小程序以短请求查询结果；Worker 最多临时保存十分钟识字结果，到期删除，不持久保存原图片。小程序过滤状态栏、聊天标题和底部输入栏，依位置把消息整理为「对方昵称：文字」或「我：文字」，检测到聊天区域的时间才记录。多行气泡尽量合并，位置不明确的内容标为「待确认」。结果按图片顺序放入上方可编辑输入框；请对照原图校正识字错误与归属后再保存。每个微信用户每天最多识别 10 张图片；与网页免费分析额度分别计数。

只有微信后台允许此 OCR 接口、Worker 已部署、AppSecret 已配置、域名被允许，并且手机网络能访问 Worker，真机 OCR 才能完成。目前不能用本地模拟代替这项真实验证。

如果截图上传直接报 `uploadFile:fail`，小程序会自动用同一张图片请求不做识字的 `/api/mini/upload-check`。自检不读取或保存图片，也不消耗识字次数；页面会显示上传链路是否到达 Worker，以便区分上传连接失败和识字接口中断。

后端 `wrangler.toml` 开启 `keep_vars = true`，避免自动部署覆盖在控制台配置的 `WECHAT_APP_ID` 普通变量；Secret 仍由 Cloudflare 保存。请勿在代码中填写 AppSecret。

## 安全与后续

聊天文字只保存在本机；**主动选择识字时，截图会发送到你配置的 Worker，再转交微信 OCR**。Worker 不持久保存图片。小程序只在本机记住 Worker 基础地址，不保存 AppSecret。已存在 v0.1.0 本机草稿时，会带入新版本输入框，不自动当成已保存的聊天记录。
